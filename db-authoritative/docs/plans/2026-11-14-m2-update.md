# M2: Update (SET and INCR) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `Store.Update` writes one or a few columns of a row to the DB with one conditional UPDATE while holding the key's `op`, and caches the row the DB returned; an Update answered OK is in the DB, and memory equals the DB whenever `op` is free.

**Architecture:** design.md 7.3 and 7.4. `Update` takes `op` (`lockOpLive`) and hands the rest to `runSync`, which runs `updateLocked` in a goroutine and releases `op` only when it returns, then answers; if the caller's ctx ends first the caller gets `ErrOutcomeUnknown` and the write finishes in the background. `updateLocked` loads if needed, checks absent / gen from the snapshot, computes the absolute new values (`applyChange`, INCR via `schema.Add`), sends `db.Update`, and stores the `RETURNING` row (the linearization point). No faults yet: ambiguous outcomes and the fence are M3.

**Tech Stack:** Go 1.25, standard library only (`testing/synctest`).

**Spec:** [design.md](../../design.md) sections 4 (I3, I4, I5, I6, I7, I11), 5.2, 6.4, 7.1, 7.3, 7.4, 8.3 (update SQL), 12.1 items 2-3, 12.2 (M2). Also [CLAUDE.md](../../CLAUDE.md) and [tla-mapping.md](../../tla-mapping.md) (the M2 rows of sections 3.1 and 5).

## Global Constraints

- All paths are relative to `db-authoritative/`; run every command from there.
- Work on branch `db-authoritative-m2` from `main` at `2674f0f`; this plan is its first commit, then one commit per task. The user reviews and merges.
- Done means: `gofmt -l .` prints nothing, `go vet ./...` is clean, `go test -race ./...` passes.
- I5: `op` is held from before `db.Update` is sent until `runSync` releases it after `updateLocked` returns; `runSync` releases `op` first, then answers (`// TLA: FinishOp`), and uses no `defer` for either (design.md 7.1).
- I7: the snapshot after an update is the row `db.Update` returned, never the row built in Go.
- INCR writes an absolute value computed from the snapshot (13.1 decision 2); the SQL shape is always `SET col = $n, ver = ver + 1 WHERE pk AND gen = ?` (8.3). The DB increments `ver`; the Store never sets it.
- Comments: invariant IDs where the code maintains them (new in M2: I4, I5, I6, I7, I11); `// TLA: X_lock`, `X_qtimeout`, `X_wait`, `B_1`, `B_2`, `FinishOp` (tla-mapping.md 3).
- **Deliberately not in M2**: `dead` and the loop of `lockOpLive` on it, `touch` (M5); `*AmbiguousError`, `fenceAndReadLocked`, `errAbandoned`, `backoff`, `ErrRejected`, statements that execute late, sessions (M3); `CheckOwner`, `ErrNotOwner`, `lostOwnership`, cancelling `bgCtx` (M6); value validation of SET values (M7). `Create`, `Delete` (M3).

### Decisions in this plan that the design does not fix

1. **`unexpectedLocked` has no owner check in M2**: it drops the snapshot and returns `ErrInternal`. `db.DB.CheckOwner`, `ErrNotOwner` and `lostOwnership` arrive together in M6 with the owner epoch; a `CheckOwner` that can only answer "owner" would be code for a later milestone.
2. **`bgCtx` is `context.Background()`**, set in `New`. The DB implementation applies `DBTimeout` per call (5.2); fakedb has no timeout. Cancelling `bgCtx` at shutdown is M6.
3. **`Update` checks the shape of a `Change` before taking `op`** and returns `ErrInvalid` for: no columns, a column out of range, a primary key column (I11), a column twice, an unknown op. Design 7.4 leaves this to the API layer (M8), but the store relies on it: an out-of-range column panics in `applyChange`, and a `Change` with no columns would send an UPDATE that only bumps `ver`. (memory-authoritative's M2 made the same call.)
4. **`lockOpLive` is `getOrCreate` + `lockOp`** until M5 adds the `dead` loop; its signature is final.
5. **fakedb's `Update` executes at once** (no late execution, no sessions: M3). Its hook sees `Stmt{Kind: Update, Key, Gen}`. fakedb gains `Normalize` (12.1 item 2: "a value normalizer") and the `OneWriterPerKey` assertion with `Violation()`.
6. **`DbVerMonotonic` holds by construction in fakedb** (it computes `ver = ver + 1` itself), so it gets no assertion; against PostgreSQL it is the SQL's `ver = ver + 1` (M7). Task 1 updates that row of tla-mapping.md 5.
7. **The test-only `opFree(e)`** (a non-blocking send and receive on `e.op`, in a `_test.go` file) checks `NoLockLeak`; production `tryLockOp` comes with eviction in M5.

## Review Focus

1. A malformed `Change` (no columns, a primary key column, a column twice, out of range, an unknown op) returns `ErrInvalid` and sends nothing. Test: `TestUpdateRejectsMalformedChange` (Task 2).
2. INCR of a NULL value, or a result out of the column's range, returns `ErrInvalid`, sends nothing, and leaves the row as it was. Test: `TestFailedIncrementSendsNothing` (Task 2).
3. An Update whose load fails returns `db.ErrNotExecuted` (UNAVAILABLE) and sends nothing. Test: `TestUpdateLoadErrorSendsNothing` (Task 2).
4. A caller whose ctx expires while its write is in flight gets `ErrOutcomeUnknown`; the write still completes, a later Get shows it, and `op` is free afterwards. Test: `TestUpdateClientGivesUp` (Task 3).
5. An Update of a missing row, or with a stale `Change.Gen`, returns `ErrNotFound`, sends nothing, and releases `op` (the next request for the key does not block). Tests: `TestUpdateMissingRow`, `TestUpdateWithStaleGen` (Task 2).

```go
// The caller's ctx expires while its write is in flight (TLA: X_wait): ErrOutcomeUnknown, and the write
// still completes in the background.
func TestUpdateClientGivesUp(t *testing.T) {
	synctest.Test(t, func(t *testing.T) {
		d := fakedb.New()
		release := make(chan struct{})
		d.Hook = func(_ context.Context, st *fakedb.Stmt) error {
			if st.Kind == fakedb.Update {
				<-release
			}
			return nil
		}
		s := newTestStore(t, d)
		k := key(t, s, 1)
		d.Put(testRow(k, 1))
		ctx, cancel := context.WithTimeout(context.Background(), time.Second)
		defer cancel()
		if _, err := s.Update(ctx, k, Change{Cols: []ColChange{set(1, "b")}}); !errors.Is(err, ErrOutcomeUnknown) {
			t.Fatalf("err = %v, want ErrOutcomeUnknown", err)
		}
		if opFree(entryOf(s, k)) {
			t.Fatal("op free while the write is still in flight (I5)")
		}
		close(release)
		s.inflight.Wait()
		if r, err := s.Get(context.Background(), k); err != nil || r.Vals[1] != "b" {
			t.Fatalf("Get = %+v, %v; want the background write applied", r, err)
		}
		checkInvariants(t, s, d)
	})
}
```
